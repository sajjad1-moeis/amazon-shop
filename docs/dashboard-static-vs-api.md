# گزارش بخش‌های استاتیک و نیازمند اتصال API — داشبورد کاربر

این سند لیست بخش‌های داشبورد را به‌صورت جدولی مشخص می‌کند: کجاها **اتصال به بک‌اند دارند** و کجاها **فعلاً استاتیک/مک هستند** و برای بک‌اند نیاز به endpoint یا قرارداد داده دارند.

## نکات برای تیم بک‌اند

1. **سفارش‌ها:** برای لیست و جزئیات سفارش به `userId` (یا توکن) و ترجیحاً فیلتر وضعیت/پرداخت نیاز است. ساختار `orderDetailData` در `src/data.js` می‌تواند به عنوان نمونه ساختار پاسخ جزئیات سفارش استفاده شود.
2. **کیف پول:** جدا کردن endpoint موجودی از endpoint تاریخچه تراکنش‌ها (با صفحه‌بندی/فیلتر) مناسب است.
3. **آدرس‌ها:** با سرویس `UserAddress` (در صورت وجود) هماهنگ شود؛ در فرانت فعلاً از `mockAddresses` و هوک `useAddresses` استفاده شده.
4. **پروفایل:** یک endpoint واحد برای پروفایل (اطلاعات اصلی + مالی + نوتیفیکیشن) یا جداگانه برای هر بخش، بسته به طراحی بک‌اند.
5. **دستگاه‌های متصل:** معمولاً همراه با نشست‌ها (sessions) و با امکان خروج از سایر دستگاه‌ها ارائه می‌شود.
6. **دعوت دوستان:** نیاز به لیست دعوت‌ها و کد/لینک معرف برای کاربر احراز هویت‌شده.
7. **پیام/نظرات:** اگر در بک‌اند جدا هستند، دو endpoint (لیست پیام‌ها، لیست نظرات کاربر) با فیلتر/صفحه‌بندی پیشنهاد می‌شود.
8. **خدمات ارزی:** احراز هویت (وضعیت موبایل/کد ملی) + CRUD درخواست‌های خدمات ارزی.
9. **مرجوعی:** لیست سفارش‌های قابل مرجوعی + لیست مرجوعی‌های کاربر + ثبت/لغو مرجوعی.
10. **قفل قیمت و سفارش انحصاری:** قرارداد دقیق با محصول/سفارش و وضعیت‌ها با تیم بک‌اند تعیین شود.
